# 守护侠 守护模块设计

版本：V0.4  
日期：2026-10-25  
项目名称：守护侠  
文档类型：Guardian Module

---

## 1. 概述

守护模块来自独立项目 GuardMyFather，按 DEVELOPMENT_PLAN 第 6.5 节迁入家人侠，代码位于 `:feature:guardian`。**C3（2026-10-20）起守护已从家人侠移除，本模块仅由独立应用「守护侠」（`:guardianapp`）使用。**

适用场景：装在**被守护的人**（通常是独居的长辈）的手机上。如果这台手机长时间没有人使用，就先大声响铃并全屏提示确认；仍然无人响应时，先给 1–3 位事先设定的**紧急联系人**群发紧急短信，再按顺序依次拨打。另外每天发送一条平安短信。

基本原则：

- 默认关闭，只有在这台手机上主动开启才会工作。
- 守护不联网：拨号和短信走运营商网络，只联系用户设定的紧急联系人。（App 不联网，见 AGENTS.md。）
- 核心指标是**不漏报**（真的出事时一定要拨出去）和**少误报**（睡觉、闲置时不乱响）。所有设计决策都服务于这两条。

## 2. 工作原理

```text
正常使用手机（解锁使用中） ──► 不计倒计时，只记“正在使用”
        │ 锁屏 / 熄屏结束使用                        │ 单次使用超过阈值仍兜底
        ▼                                           ▼
   从锁屏时刻开始倒计时                      使用中上限（= 正常阈值）到期
        │ 超过阈值（默认 8 小时）没有再用手机        │
        └───────────────┬───────────────────────────┘
                        ▼
              手机大声响铃 + 震动 + 全屏确认页
              倒计时（默认 2 分钟）等待确认
                    │
        ┌───────────┼───────────────┐
        │ 点“我没事”或解锁手机       │ 倒计时结束仍无人响应
        ▼                           ▼
   取消响铃，重新计时          先给所有紧急联系人群发紧急短信
                               （说明情况，提示“接通后没人说话
                                 请立即上门”）
                                     │
                                     ▼
                          依次拨打联系人 1 → N（尽量开免提）
                          每通结束后查通话记录判定是否接通
                                     │
              ┌──────────────────────┼──────────────────────┐
              │ 有人接通              │ 一轮无人接通
              ▼                      ▼
        按策略收尾：           3 分钟后从第 1 位再拨一轮，
        接通即停 或           最多 2 轮
        拨完所有人                     │
              └──────────────┬───────┘
                             ▼
                    群发结果短信（谁已接听 / 无人接听），ALERTED

任一阶段解锁或点“我没事”：停止拨号与后续闹钟，
若已发出紧急短信则群发“已解除”，回到守护中。
```

## 3. 什么算“使用了手机”

| 行为 | 是否算活动 | 说明 |
|---|---|---|
| 解锁手机（指纹 / 人脸 / 密码 / 上滑） | 算 | 最可靠的“有人在操作”信号 |
| 解锁使用后再锁屏/熄屏 | 算 | 使用会话结束，从这一刻开始倒计时 |
| 接听来电、拨打电话 | 算 | 有些长辈主要用手机接打电话 |
| 在确认页点“我没事” | 算 | 手动确认平安 |
| 来消息或来电时屏幕亮一下又灭 | 不算 | 人晕倒时消息照样会来 |
| 未接来电响铃 | 不算 | 没人接听不代表人没事 |
| 开机、充电 | 不算 | 可能是自动发生的 |
| 守护自己拨出的报警电话 | 不算 | 过滤覆盖整个拨号序列直到最后一通之后 3 分钟：序列进行中没有新来电响铃的摘机一律过滤；序列结束后、最后一通拨号起 3 分钟内且期间没有新来电的摘机也不算 |

前提：被守护的手机必须设置锁屏（上滑、图案、密码、指纹或人脸都可以，不能是“无”），否则“解锁”信号不可靠。

## 4. 状态机

```text
DISABLED ──开启──► MONITORING ──到期──► CONFIRMING ──倒计时结束──► ALERTING ──拨出电话──► ALERTED
   ▲                  ▲                      │                                            │
   └──停止守护────────┴──── 任何活动 ─────────┴──────────────── 任何活动 ──────────────────┘
```

- MONITORING：正常监测。每次活动都重新计算截止时间。手机正在使用（解锁会话中）时不计倒计时，截止时间按“使用中上限”计算；锁屏后从锁屏时刻按正常阈值倒计时。
- CONFIRMING：已到期。响铃并全屏提示，等待“我没事”；期间任何解锁或通话同样会取消报警。
- ALERTING：拨号序列进行中。持久化的子步骤为 START（发紧急短信）→ DIALING → CHECKING（查通话记录判定是否接通）→ 下一位或 ROUND_WAIT（等下一轮）；最多 2 轮。
- ALERTED：序列已结束（有人接通按策略收尾，或两轮无人接通）；拨号途中关闭守护也收敛到此。解除则直接回到 MONITORING。

报警期间有新来电并接听算活动（会解除，回到 MONITORING）；任何活动事件或"我没事"停止拨号、若已发紧急短信则群发"已解除"。序列全程持久化，进程被杀后恢复时从持久化步骤续上（先补查未判定的那通，不重拨、不重复群发）。

所有状态变化都只通过 `GuardEngine.handle(Event)` 这一个入口完成。引擎是纯 Kotlin，通过 `Clock` 和 `Ports` 接口与系统交互，全部状态流转都有 JVM 单元测试覆盖。

## 5. 计时规则（业务契约）

- **活动事件**：解锁（USER_PRESENT）；解锁会话之后的熄屏；非自拨号的摘机；点“我没事”；从系统使用记录中找回的解锁事件。
- **使用会话（inUse）**：解锁开始、锁屏结束。会话进行中不计倒计时（状态卡显示“正在使用”）；报警流程（CONFIRMING 及之后）中的熄屏只结束会话，**不算平安**、不取消响铃。
- **截止时间**：
  - 使用中：截止时间 = 上次活动 + 使用中上限（= 正常阈值）。一次使用持续超过阈值（视频循环、屏幕常亮）照样响铃；**使用中上限不受测试模式影响**。
  - 锁屏后：截止时间 = 上次活动 + 阈值（默认 8 小时，可选 1–24 小时；测试模式 30 秒）。严格模式，没有夜间豁免。
- **到达截止时间**：
  1. 先查系统使用记录，补回可能漏掉的解锁事件；
  2. 仍然过期，则进入 CONFIRMING：响铃、全屏通知，确认截止时间 = 现在 + 确认时长（默认 2 分钟；测试模式 15 秒）。
- **到达确认截止时间**：进入 ALERTING，开始报警拨号序列：
  1. 先给所有紧急联系人群发紧急短信（短信先于拨号，已发出则持久化置位防重复群发）；
  2. 从第 1 位依次拨号（持久化 DIALING 后才真正拨出）；
  3. 判定接通：通话记录中本次拨出 + 号码匹配 + DURATION>0 才算接通；IDLE 后延迟 3 秒查，读不到每 5 秒重试共 4 次；另有拨号后 3 分钟兜底闹钟，仍在通话中则每 60 秒再等；
  4. 读不到记录、无权限、placeCall 失败一律按"未接通"继续下一位（宁可多打不漏报）；
  5. 按「有人接通后」策略收尾：接通即停（默认）或拨完所有人；
  6. 一轮无人接通：3 分钟后从第 1 位再拨一轮，最多 2 轮；
  7. 收尾时群发结果短信（谁已接听 / 多次拨打无人接听）；
  8. 解除（我没事 / 活动事件）：停止拨号与序列闹钟，若已发紧急短信则群发"已解除"。
- **每日平安短信**：开启时每天在设定时刻（默认 09:00）发给所有紧急联系人，然后预约下一天；报警流程中（CONFIRMING/ALERTING/ALERTED）不发。
- **任何活动事件**：回到 MONITORING；停止响铃；取消确认相关的闹钟；重新计算截止时间并挂闹钟。
- **开机、应用更新、修改时间**：
  - 如果守护已开启：确保前台服务在运行。
  - 截止时间已过：先进入响铃确认，不直接拨号。
  - 截止时间未过：按持久化的状态补挂所有闹钟。
- **看门狗**：每 30 分钟自查一次，确保服务存活、截止时间没有被系统吞掉，并自动修复；顺带做会话对账（见下）。守护已关闭时直接返回，不拉起服务。
- **会话对账（SyncSession）**：前台服务启动、看门狗自查、守护页可见时，引擎用 `PowerManager.isInteractive && !KeyguardManager.isKeyguardLocked` 校对“正在使用”标记：漏掉的解锁补记一次使用，漏掉的熄屏则保守地从上次活动按锁屏后阈值重新计时。对账只在 MONITORING 下进行，屏幕状态永远不能取消报警。对账后同时补挂截止、确认结束（只补挂、不在此拨号）、平安短信与看门狗闹钟，应对进程被杀后闹钟丢失（注：这里的“进程被杀”指系统回收，不是用户强行停止；强行停止见第 11 节）。
- **开机/更新/看门狗/SyncSession 对 ALERTING 序列的处理**：从持久化步骤续上——正在拨/查的那通先补查通话记录判定结果，不重新拨号、不重复群发已发过的短信；轮间等待则补挂下一轮闹钟。
- **开启前提**：紧急联系人列表非空 + 当前设备的有效演练记录。

## 6. 可靠性设计

小米、vivo 等系统会主动杀后台，以下机制共同保证守护持续有效：

| 机制 | 作用 |
|---|---|
| 前台服务（specialUse 类型） | 动态注册屏幕亮灭、解锁广播（这些广播不能静态注册） |
| AlarmManager `setAlarmClock` | 到期、确认结束、平安短信的定时，不受 Doze 影响 |
| 拨号序列闹钟（requestCode 7–9） | 通话记录检查 / 拨号兜底 / 下一轮的重试，进程被杀后到点照走 |
| 序列进度持久化 | `alertSeq` 子步骤与 `alertSmsFlags` 写盘，恢复时续上不重拨不重发 |
| 短信 sentIntent 回传 | 每条短信（含多段）带 kind/index 回执，失败即知（`SmsSentReceiver`） |
| 看门狗闹钟 | 每 30 分钟自查服务是否存活、状态是否过期 |
| 开机与更新广播（含 LOCKED_BOOT_COMPLETED） | 重启或升级后继续守护 |
| Direct Boot | 重启后尚未解锁也能响铃、拨号：状态、配置、紧急联系人都存放在设备加密存储区 |
| 使用情况访问（可选） | 兜底：服务被杀期间漏掉的解锁事件，到期时从系统记录中找回 |
| 事件日志 | 最近约 300 条关键事件写入文件，可在守护页查看，便于排查 |
| 最低重要性状态通知渠道 | 常驻通知用 IMPORTANCE_MIN（无状态栏图标），关闭守护即消失 |

工程约定：

- 一切将来要发生的事都用 AlarmManager 落盘调度，禁止用进程内延时承担业务时序（进程随时可能被杀）。
- 广播接收器必须幂等、可重入、可乱序处理。

## 7. 权限与系统设置

### 7.1 运行时权限（开启守护时申请）

| 权限 | 用途 |
|---|---|
| 拨打电话（CALL_PHONE） | 无人确认时自动拨打紧急联系人 |
| 读取通话状态（READ_PHONE_STATE） | 接打电话算作使用 |
| 发送短信（SEND_SMS） | 紧急短信、演练测试短信、每日平安短信；必需 |
| 读取通话记录（READ_CALL_LOG） | 只用于判断守护侠自己拨出的那几通电话是否接通；必需 |
| 通知（POST_NOTIFICATIONS） | 守护状态与到期确认 |

### 7.2 权限清单页的结构

权限清单页分两组，全部必需项就绪是开启守护的必要条件之一：

- **自动检测**：逐项给出三态——已开启 / 未开启 / 检测不到。
  运行时权限（拨号、电话状态、短信、通话记录、通知）点“去开启”直接弹系统授权框；
  被拒后才回退应用详情页。检测不到的必需项不冤枉用户——
  降级到下面的“需要手动确认”组，不永远红灯。
- **需要手动确认**：代码无法检测的必需项（自启动、省电策略无限制、
  最近任务加锁、小米拨号始终允许、锁屏通知）逐项跳转系统页 +
  用户勾选“我已设置”。确认记录持久化并绑定 `Build.FINGERPRINT`：
  系统升级后指纹变化 → 全部确认项失效，需重新确认。

新增检测项：**未使用应用限制豁免**（Android 11+ 应用休眠/自动收回权限；
长辈从不打开本应用，必须豁免。`PackageManagerCompat.getUnusedAppRestrictionsStatus`
为异步查询，不阻塞主线程，结果回填后刷新）。

### 7.3 手机厂商设置（以小米 / 红米 / 澎湃 OS 为例）

| 设置项 | 为什么必须 |
|---|---|
| 自启动：允许 | 否则闹钟和广播无法唤起被杀掉的进程 |
| 省电策略：无限制 | 否则锁屏后进程被冻结，收不到屏幕广播 |
| 最近任务中加锁 | 防止清理内存时被划掉 |
| 后台弹出界面：允许 | 到期时需要弹出全屏确认页（反射读不到时归“手动确认”，不硬判失败） |
| 拨打电话：始终允许，并勾选“记住选择” | 否则每次拨号都会弹确认框，报警会失效 |
| 锁屏通知：允许 | 守护状态与确认通知要在锁屏上显示 |

### 7.4 与家人侠整体权限原则的关系

- 上述权限由守护模块的 Manifest 声明。这是 ARCHITECTURE 第 31 节“避免直接拨号高权限”的唯一例外，仅用于无人值守的紧急拨号。
- 不使用守护功能的手机不会被申请这些运行时权限。
- 守护模块不使用网络；App 整体不联网（AGENTS.md 约定）。

## 8. 隐私

- 守护的配置与状态保存在这台手机的设备加密存储区，**不包含在家人侠的备份文件中**，也被排除在系统云备份和设备间迁移之外（见 `backup_rules.xml`、`data_extraction_rules.xml`）；换机后需要重新设置。
- 日志和事件日志中的手机号一律打码（只保留前 3 位和后 4 位）。
- 通话记录只在报警/演练期间查询，且只查守护侠自己拨出的那几通（拨号时刻之后、号码在紧急联系人列表中）；只在内存中比对是否接通，不读取其他记录、不保存任何通话记录内容。
- 短信只发给紧急联系人（紧急短信 / 结果短信 / 已解除 / 测试短信 / 平安短信）。平安短信的内容：最后一次使用手机的时间、距今多久、电量和是否在充电。
- 不读取通讯录全部内容：从通讯录选择紧急联系人时，使用系统联系人选择器，只读取所选的那一个号码。

## 9. 与家人侠的集成

- **模块边界**：`:feature:guardian` 不依赖 Hilt，不访问 Room，也不依赖 `:app`。它使用自己的轻量 ServiceLocator，以保证手机重启后、解锁前也能独立运行。
- **对外接口**：
  - 守护页入口组件 `GuardianTab`；
  - 由应用提供的“家人号码来源” `GuardianContactSource`：列出有在用号码的家人，只在选择紧急联系人时读取。
- **启动顺序**：应用启动时先初始化守护模块。如果用户尚未解锁，不启动生日提醒同步，也不访问 Room 和 DataStore，避免崩溃；收到解锁广播后再启动。
- **通知**：守护使用独立的通知渠道（`guardian_status_quiet`、`guardian_confirm`、`guardian_result`）和通知标签 `guardian`，与生日提醒互不干扰。状态渠道为 IMPORTANCE_MIN，不在状态栏显示图标；前台服务的状态通知不带标签（与 startForeground 共用 id），关闭守护即消失。点击守护通知会回到家人侠主界面。
- **界面**：守护页使用 `:core:designsystem` 中的统一主题与组件，守护侠固定使用暖白浅色主题（字号仍跟随系统），内部分五屏：
  - 主页：未开启时是四步设置向导——说明卡 + ①紧急联系人 ②权限与系统设置（自动检测 x/y · 手动确认 m/n）③实机演练（上次结果摘要）+ 主按钮永远指向下一步；开启后显示状态卡、运行状态、常驻“实机测试”入口卡与红色异常卡（必需项被收回 / 演练记录失效 / 手动确认失效时列出原因）。报警进行中显示序列进度卡：第几轮 / 每位联系人一行状态（正在拨打、已接听、未接通、等待拨打/未拨打）、紧急短信是否已发出、轮间等待时刻，以及“我没事”解除按钮。
  - 设置：紧急联系人列表（1–3 位，可增删、上移/下移排序；顺序即拨打顺序）、「有人接通后」策略单选（接通即停 / 拨完所有人）、无活动阈值、确认时长、夜间免打扰、每日平安短信（含“发送一条试试”）、权限与演练入口、隐私说明与版本信息。
  - 权限清单：自动检测（三态）与需要手动确认两组。
  - 实机演练：等待时长 1/10/30/60/120 分钟可选（<30 分钟只作快速检查，不计入开启条件）。
  - 事件日志。
- **开启流程与门槛**：主按钮始终可点、指向下一步；点“开启守护”时先弹后果确认框，再由引擎做硬性门槛判定——紧急联系人列表非空、且存在当前设备上的有效演练记录（通过 + 等待 ≥30 分钟 + App 版本/系统指纹/整个联系人列表（顺序+号码）与当前一致），否则拒绝开启并记录原因。
- **实机演练**：独立于守护开关的持久化状态机——等锁屏 → 等待（锁屏时刻 + 等待时长挂独立闹钟）→ 到点响铃并弹“这是守护测试”全屏页 → 确认窗口结束后给每位联系人发一条测试短信并按顺序各拨一次 → 逐位询问“收到短信/接到电话了吗” → 写演练结果。结果含逐项判定（到点响铃 ≤60 秒延迟 / 全屏页弹出 / 每位四项：测试短信已发出、电话已接通、用户确认收到短信、用户确认接到电话）与环境指纹；App 升级、系统升级、增删/改号码/调整联系人顺序都会使记录失效（只改名不失效）；演练记录结构升级（schema）同样使旧记录失效。演练只发「守护侠·测试」前缀的测试短信，绝不发真实紧急短信与平安短信；演练拨号与摘机不计入真实使用；真实报警永远优先，演练进行中触发真实确认则演练中止。开启后再测不影响守护行为；演练记录失效不会自动关闭已开启的守护。
- **锁屏确认页**：强制浅色、高对比度、超大按钮（“我没事” / “立即呼叫”），在锁屏之上显示。

## 10. 在长辈手机上的设置步骤（设置向导）

1. 在长辈手机上安装守护侠。如果之前装过 GuardMyFather，先在其中停止守护，再卸载它，避免两个应用重复报警。
2. 打开守护侠，首页就是四步向导，主按钮永远指向下一步：
   - ① 紧急联系人：从系统通讯录选择或手动输入，可设 1–3 位，顺序就是拨打顺序（守护侠没有家庭档案）。
   - ② 权限与系统设置：权限清单分“自动检测”与“需要手动确认”两组，逐项完成（含第 7.3 节厂商设置）。
   - ③ 实机演练：可先做一次 <30 分钟的快速检查（可选），再做 ≥30 分钟完整测试——锁屏放着别动，到点会响铃、弹出“这是守护测试”全屏页，然后给每位联系人发一条测试短信并依次拨打，每位都要收到短信并接听，回来逐位确认。
3. 全部就绪后点“开启守护”，确认后果说明即生效。
4. 之后增删联系人、改号码、调整顺序、升级 App、系统升级都会使演练记录失效：守护保持运行，但首页会提示需要重新测试；未通过完整测试前无法在新设备上直接开启。

## 11. 实机演练与真机回归清单

### 演练规则

- 等待时长：1/10/30/60/120 分钟可选；<30 分钟为快速检查，≥30 分钟才计入开启条件。
- 等待期间解锁或亮屏使用 → 演练中止（不算失败）；点“停止测试”中止。
- 判定项：到点响铃（延迟 ≤60 秒）、全屏测试页在锁屏上弹出；然后逐位四项全 ✓——测试短信已发出（sentIntent 回执）、电话已接通（通话记录判定）、用户确认收到短信、用户确认接到电话。
- 演练给每位联系人发一条「守护侠·测试」短信并各拨一次（不论接听策略），绝不发真实紧急短信与平安短信；演练号码在日志中打码。

### 开发快速阈值（仅调试包）

原“测试模式”已改为 `devFastThresholds`：无活动阈值 30 秒、确认 15 秒、
免打扰关闭、使用上限仍 8 小时。仅调试包在设置页可见此开关；
正式包即使存储残留旧值也强制读为关闭（GuardStore 按
`ApplicationInfo.FLAG_DEBUGGABLE` 判定）。用途是开发者真机回归
正常守护链路，不是给用户的测试入口——用户验证走上面的实机演练。

### 真机回归清单（用用户同意的安全号码，绝不用真实家人号码）

1. 新装走完整向导：①②③ 逐步完成，观察每一步主按钮指向。
2. 演练：等待中解锁 → 中止；点“停止测试” → 中止；响铃时看锁屏全屏页与倒计时；
   每位联系人收到测试短信、按顺序各响一次电话并接听 → 逐位回答两问 → 结果卡逐位四项通过。
3. 正式守护（可用开发快速阈值回归，正式阈值同理）：
   - 开启后使用中显示“正在使用”，不计倒计时；
   - 锁屏后开始倒计时，到点响铃并出现全屏确认页；
   - 点“我没事”回到守护中、重新计时；
   - 不操作，确认窗口结束：所有联系人先收到紧急短信，之后才响第 1 位电话；
   - 第 1 位接听（接通即停策略）→ 其他人不再被拨打，所有人收到“已由 X 接听”；
   - 切到“继续拨打所有联系人”再测：第 1 位接听后仍拨第 2 位，全部拨完收到汇总短信；
   - 所有人都不接 → 约 3 分钟后第 2 轮再拨一遍 → 收到“多次拨打无人接听”，
     首页报警卡的轮次与每人状态显示正确；
   - 拨号途中解锁 → 不再拨打后续联系人，所有人收到“已解除”；
   - 序列进行中划掉应用（非强行停止）→ 到点仍续走，不重复收到紧急短信、已判定的那通不重拨；
   - 关闭守护后状态通知消失，通知栏只保留一条状态通知（无 tag，
     渠道 guardian_status_quiet）。
4. 只按电源键亮屏再熄灭（不解锁），不重新计时；解锁后再锁屏，重新计时。
5. 拨打或接听任意电话后，重新计时。
6. 进程结束要区分三种方式，按 Android 官方行为验证，引擎不为绕过强行停止做特殊处理：
   - **强行停止**（设置 → 应用信息 → 强行停止）：闹钟、广播全部失效——系统规定，不是缺陷。验证：强停后重新打开应用，守护自动恢复。
   - **系统回收**（内存不足杀死进程）：闹钟仍有效，到点照常响铃。
   - **最近任务划掉**：只结束界面和进程；到点仍应响铃（小米需完成白名单设置）。
7. 重启手机、不解锁：日志中有开机恢复记录，到期仍能响铃。
8. 每日平安短信能发到测试号码，且号码在日志中是打码的。
9. 更换紧急联系人后：演练记录变“已失效，需要重新测试”，开启中被保留；
   状态通知变“守护可能失效，请打开查看”；守护期间状态通知始终只有一条。
10. 可选故意失败路径：不给省电策略无限制/自启动，30 分钟等待中后台被杀，
    解锁后看到“闹钟没有响铃”的失败记录。

## 12. 局限性

- 手机没电、欠费、取出 SIM 卡、开飞行模式时无法报警。每日平安短信可以帮助侧面发现：哪天没收到，就该打电话问问。
- 设置了 SIM 卡 PIN 码的手机，重启后要先输入 PIN 才能拨号，建议去掉 SIM PIN。
- 已实现轮流重拨（最多 2 轮 × 多位联系人），但仍有局限：无法往通话里放语音，所以靠紧急短信说明情况；通话记录写入有延迟、个别 ROM 号码格式差异——判定失败一律按未接通多打（宁可多打不漏报）。
- 用户在系统设置里“强行停止”应用后，闹钟与守护不再生效，直到用户重新打开应用——这是 Android 的规定行为，不为此做引擎上的绕行。
- 系统大版本升级后，建议重新检查一遍权限清单。
